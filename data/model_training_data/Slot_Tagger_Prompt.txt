The output must preserve the original token order. Return the result as a downloadable csv with the same columns as the given csv.

Do not explain your answer unless I explicitly ask for an explanation.
The world values can be given as one token with _ or as splitted words.

Labels
######

Use these labels:

O
Outside any slot.

B-OBJECT_ID
An object ID token, if it follows the generated ID schema like `shoe_1`, `repair_tool_2`, `cleaning_utensil_3`, etc.

B-SHOE_TYPE
Shoe type such as sandal, sneaker, boot.

B-COLOR
Shoe color.

B-MATERIAL
Shoe material such as canvas, suede, rubber, leather.

B-SHOE_HEIGHT
Shoe height such as high, low, mid, tall, small.

B-CLEANING_STATUS
First token of a shoe cleaning status.

I-CLEANING_STATUS
Continuation token of a multi-token cleaning status.

B-IMPREGNATION_STATUS
First token of an impregnation status.

I-IMPREGNATION_STATUS
Continuation token of a multi-token impregnation status.

B-MATERIAL_STATUS
Material condition such as good, scratched, cracked, damaged, broken.

B-DRY_STATUS
Dry status such as wet, dry, damp, soaked.

B-DIRT_TYPE
Dirt type such as mud, muddy, sand, sandy, grass, oil, oily, dust, dusty.

B-SOLE_STATUS
Sole condition such as worn, loose, intact, damaged, broken.

B-CLEANING_TOOL_TYPE
Cleaning utensil type such as brush, cleaner, rag, cloth, towel.

B-IMPREGNATION_TOOL_TYPE
Impregnation utensil type such as spray, cream, wax.

B-REPAIR_TOOL_TYPE
First token of a repair tool type.

I-REPAIR_TOOL_TYPE
Continuation token of a multi-token repair tool type.

B-REPAIR_TARGET
Repair target such as sole, underside, material, fabric, surface, upper.

B-THRESHOLD
A numeric threshold or percentage number, such as 30, 30%, 80, 80%....

I-THRESHOLD
Continuation of a threshold phrase, such as `%` or `percent`.

B-OBJECT_LOCATION
First token of a location phrase that describes where an object currently is.

I-OBJECT_LOCATION
Continuation token of a describing object location phrase.

B-TARGET_LOCATION
First token of a location phrase where an object should be moved or put down.

I-TARGET_LOCATION
Continuation token of a target location phrase.

B-WALK_PLACE
First token of a walk place.

I-WALK_PLACE
Continuation token of a multi-token walk place.

B-WALK_WEATHER
First token of weather information for a walk.

I-WALK_WEATHER
Continuation token of multi-token weather information, such as "dry weather" or "wet weather".

B-WALK_LENGTH
Walk length such as short, medium, long, quick, brief, normal, regular, far, extended.

B-BEFORE_SENTENCE_SPLIT
The token that splits the shoe phrase from the tool phrase in CLEAN, IMPREGNATE, and REPAIR commands and the shoe in question is described befor the split word. Usually this is the case for: with, using, or by using.

B-AFTER_SENTENCE_SPLIT
The token that splits the shoe phrase from the tool phrase in CLEAN, IMPREGNATE, and REPAIR commands and the shoe in question is described after the split word. Usually this is the case for: use ... to, apply ... on,...

B-TARGET_LOCATION_RELATION
First token of a relation introducing a target location in MOVE or PUT_DOWN commands. on,in,into,onto,...

I-TARGET_LOCATION_RELATION
Continuation token of a multi-token target location relation.

B-TARGET_NEXT_TO_RELATION
First token of a relation introducing a target next-to object in MOVE or PUT_DOWN commands. usually 'next to' or 'beside'

I-TARGET_NEXT_TO_RELATION
Continuation token of a multi-token target next-to relation.

B-LOCATION_RELATION
First token of a relation introducing a describing object location, not a movement target. on,in,into,onto,...

I-LOCATION_RELATION
Continuation token of a multi-token describing location relation.

B-NEXT_TO_RELATION
First token of a describing next-to relation. usually 'next to' or 'beside'

I-NEXT_TO_RELATION
Continuation token of a multi-token describing next-to relation.


Important relation rules
########################

For MOVE commands:
------------------
The last spatial relation in the command is the target relation.
All earlier spatial relations describe the object that is being moved or put down.
Examples:

- "next to" describes the green sandal.
- "boot" is the describing object.
- "on" is the target location relation.
- "top shelf" is the target location.

For PUT_DOWN commands
---------------------

Here the logic is a little diffrent.
The target relation is found in this order:
-- first next to relation is the target relation, all following relations describe the object that is reffered to in this relation
-- if there is no next to relation, then the first on/inside relation is the target relation all following on/inside relations are to be ignored.
If a MOVE or PUT_DOWN command contains only one relation, that relation is the target relation.

Command:
move the boot to the floor

move O
the O
boot B-SHOE_TYPE
to B-TARGET_LOCATION_RELATION
the O
floor B-TARGET_LOCATION

Ambiguity rules
###############

If a word could belong to multiple slots, choose the slot that matches its semantic role in the command.
Examples:

"material" in "repair the material" is a repair target:
material B-REPAIR_TARGET

"canvas" in "canvas shoe" is a shoe material:
canvas B-MATERIAL

"dirty" in "dirty boot" is a cleaning status:
dirty B-CLEANING_STATUS

"muddy" in "muddy boot" is a dirt type:
muddy B-DIRT_TYPE

"wet" in "wet boot" is a dry status:
wet B-DRY_STATUS

"with" in tool commands is B-SENTENCE_SPLIT, not a relation.


Articles and filler words such as the, a, an, please, me, my, this, that, of, from, down, up are usually O unless they are part of a multi-token canonical phrase.

Do not normalize the tokens. Keep the original token text.
Do not combine tokens.
Do not skip tokens.
